# respawnkeeper

**ゲームサーバーが落ちたら、1回目で原因を特定し、直せるものだけ直して、起こし直す。直せないものは止まって人を待つ。**

Windows / PowerShell 5.1 で動く、ゲームサーバーの見張り役。
友人と遊ぶ Minecraft（Forge / NeoForge）のサーバーを見るために作り、あとから Valheim などへ広げた。
ゲームごとの違いは `harness/games/<id>.psd1` にデータとして出してあり、司令塔のコードはゲームを1つも知らない。

> 使い方の詳細は [harness/README.md](harness/README.md)。このページは「何を考えて作ったか」を先に書く。

---

## 落ちたとき、中で何が起きるか

```
サーバーのプロセスが終わる
  ├ 人が止めた（停止の手順がログに残っている）──▶ 何もしない。絶対に起こし直さない
  ├ 証拠が何も無い（タスクマネージャ・窓を閉じた）──▶ 起こし直さない
  └ クラッシュ（crash-report・hs_err・ログ末尾の例外）
       ├ ① サーキットブレーカー   30分に3回落ちたら止まって人を待つ（外せない）
       ├ ② 表引きの診断           実際に起きたクラッシュから作った規則と突き合わせる（モデル不使用）
       │     ├ 一過性             そのまま再起動
       │     ├ 直せると分かっている 停止中に隔離か退避をして再起動（消さない。元に戻せる）
       │     └ 人の判断が要る      止まる（許可していればモデルへ渡す）
       └ ③ 直したのにまた落ちた ──▶ 再試行しない。止まる
```

## 設計で決めたこと

| 決めたこと | 理由 |
|---|---|
| **原因の特定を段に切る**（表引き → モデル） | 繰り返し落ちるクラッシュは、同じ mod が同じ理由で落ちている。表で片付くものにまでモデルを呼ぶと、費用だけが増える |
| **自動再起動の既定は OFF**。修復は停止中にだけ行う | 動いているサーバーのファイルを書き換える事故を、仕組みで起こせなくする。「止まっている」は宣言ではなく、ポート・PID ファイル・プロセスを毎回機械で確かめる |
| **手で止めたものは再起動しない** | 終了コードでは「人が止めた」と「落ちた」を区別できない。証拠が無いときは再起動しない側に倒す。起こし直す手間は1回で済むが、作業中のサーバーを勝手に起こされる方が高くつく |
| **mod を外すのは3つの条件が揃ったときだけ**（原因が一意・道連れが0・配布していない） | 「N回落ちたら外す」は、しつこさを測っているだけで、外したら直るかを測っていない。依存している mod が多いものを1個外すと、実際には何十個も外れる |
| **強制終了に格上げしない** | ゲームによっては、強制終了で失うのは前回の自動保存以降の全部。止まらなければ手を引いて人に知らせる |
| **ゲームごとの違いはデータに出す** | 起動・停止・ログの場所・クラッシュの見え方・直してよい場所の5つを `games/<id>.psd1` に書く。人が停止を1回見届けるまで、そのゲームの自動再起動は自動で OFF |
| **状態はサーバーの隣に置く**（`<サーバー>\respawnkeeper\`） | 見張り役の隣に置くと、複数のサーバーの記録が1つに混ざって読めなくなる |
| **入口の判断は1か所**（`harness/rk-entry.ps1`） | 以前は exe と bat で同じ名前なのに動きが違い、同じ欠陥を2回直すことになった |

## 構成

```
respawnkeeper.bat / panel.bat      ダブルクリックの入口（判断は持たない）
servers.example.json               見るサーバーの登録簿の例（servers.json に写して使う）
harness/
  respawnkeeper.ps1                司令塔。起動 → 終了の検知 → 診断 → 修復 → 再起動か停止
  rk-entry.ps1                     入口の判断はここだけ
  rk-setup.ps1                     サーバーのフォルダを調べて、そのサーバー用の設定と bat を作る
  rk-diagnose.ps1                  表引きの診断（読むだけ）
  rk-repair.ps1                    修復（既定は試し実行。隔離だけで、消さない。-Undo で戻す）
  rk-logscan.ps1                   毎日の点検。落ちずに溜まっている問題を数えて報告する
  rk-lock.ps1                      修復中の排他ロック
  rk-newgame.ps1                   知らないゲームのテンプレートを作る
  games/*.psd1                     ゲームごとの5つの答え
  rules/*.psd1                     診断と点検の規則（根拠の欄が必須）
  lib/                             共通の関数（生存の判定・ログの読み方・依存グラフ）
  hooks/                           表で片付かないときにモデルへ渡す部分
  ui/                              操作パネルとコンソール（WPF）
  launcher/                        exe の元（Windows に付いている csc.exe だけでビルドする）
  tests/                           自己テストと検体
```

## 動かす

前提: Windows・PowerShell 5.1。Minecraft を見るなら Java。

```powershell
# 何も起動しない確認（いつでも安全）
powershell -File harness\respawnkeeper.ps1 -ServerDir "<サーバーのフォルダ>" -CheckOnly

# 自己テスト（捨てフォルダで動く。登録したサーバーには書かない）
powershell -File harness\tests\Invoke-SelfTest.ps1
```

`respawnkeeper.exe` は同梱していない。`harness\launcher\build-exe.ps1` で作るか、`respawnkeeper.bat` を使う。
設定に使う環境変数は [.env.example](.env.example)。

## 検証の状況

ゲームごとの検証の状況は `harness/games/<id>.psd1` の `verified` が正本。
Minecraft は配置・起動・停止まで確かめてある。それ以外は、テンプレートごとに確かめた範囲が違う。
**実運用のサーバーで自動修復が発火した実績は、まだ無い。** 規則は実際のクラッシュ報告から作ったが、的中率は測れていない。

## 同梱していないもの

- **判断の記録と知識の文書。** コードのコメントにある `[R-012]` のような番号は、非公開の判断ログの番号。
- **絵の作業ファイル**（下書き・落選案・拡大・参考）。実行時に読むスプライト（`harness/ui/stage/art/*.rkspr`）と、その取り込み元の画像だけを入れてある。
- ステージの絵は、画像生成（ComfyUI）で作った原画を取り込み、手で直したドット絵。`harness/ui/stage/` のスクリプトはその作業用で、見張りの機能とは関係しない。
